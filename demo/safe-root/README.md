# Safe roots over a million floats

`safe_root.rk` defines one `Samples` pack, a `safe_root` rake and a `roots`
run over a stack's `f32` column. `safe_root.c` performs the same operation
with a C `for` loop and an `if`: non-negative values take their square roots,
and every other value becomes zero.

Run the bounded four-way comparison in the pinned development shell:

```sh
nix develop --command dune build -j 1 src/bin/main.exe
nix develop --command bash demo/safe-root/run.sh
```

The Rake profile is AVX2: eight floats in a 256-bit register. The compiler
generates the complete loop and advances by eight elements per iteration.
One million elements require 125,000 full racks. A second correctness pass
uses 1,000,003 elements, including a three-lane final rack. Rake's native
object verifier checks the complete function against its selected assembly.
Generated C, objects, disassemblies and `timings.tsv` go under
`.build/safe-root/`.

The independent C harness compares every result bit, checks empty counts,
all tail remainders, exact in-place output and allocations ending at guard
pages. Negative zero, quiet NaNs, infinities and ordinary signed inputs are
included. All four kernels agree on result bits, including exact in-place
updates. Rake and the intrinsic implementation also suppress arithmetic
exceptions in inactive lanes. Ordinary C comparisons can raise `FE_INVALID`
for a quiet NaN. A two-column
fixture also compares the native program with Rake's selected-profile
interpreter, including an unused byte column and a one-lane tail.

The timing input is one million pseudo-random finite floats, roughly half
negative, generated by xorshift32 from seed `0x31415926`. Four warmups precede
31 timed samples, with the four kernels rotating through execution order. Each sample
averages four complete passes and the report gives the median. The arrays
share the same initial data, and no link-time optimization is enabled.

Three C builds are reported. The ordinary optimized build uses GCC `-O3
-mavx2 -ffp-contract=off -fno-fast-math -fno-math-errno`. Its automatic
vectorizer is enabled. The explicitly scalar comparison adds
`-fno-tree-vectorize`. `safe_root_avx2.c` uses explicit eight-lane AVX2
instructions and masked memory operations for the tail. The fourth kernel
is the complete Rake traversal. The report retains every sample, the median,
source and artifact hashes, flags, GCC version and processor.

The retained [4 October measurement](measurement-20261004.tsv), on a Ryzen
7 5800X3D with GCC 14.3, has these medians per million-element pass:

| Kernel | Milliseconds |
| --- | ---: |
| C, vectoriser disabled | 3.87 |
| C, automatic vectorisation | 0.143 |
| C, AVX2 intrinsics | 0.143 |
| Rake, verified AVX2 traversal | 0.144 |

The three vector implementations have similar times. Rake verifies the
selected vector instructions and the complete traversal.

## Rejection and algorithm change

The runner also compiles the existing strict sine comparison from
`demo/soa-proof`. GCC accepts its per-element `sinf` calls. Rake rejects
the native rack sine with `call to 'sin' is not supported by native scratch
lowering`.

`bounded_sine.c` and `bounded_sine.rk` replace that general operation with a
ninth-degree polynomial for angles in `[-0.5, 0.5]` radians. GCC vectorises
the inline C polynomial, and Rake's AVX2 object passes verification.
An independent `sinf` reference checks 8,000 evenly spaced inputs. Both
versions' maximum observed absolute error is `2.98023224e-8`.
The runner retains this result in `bounded-sine.tsv` and disassembles the
accepted code. The polynomial's domain and accuracy belong to this example's
algorithm contract.
