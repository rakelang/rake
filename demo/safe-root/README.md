# Safe roots over a million floats

`safe_root.rk` defines one `Samples` pack, a `safe_root` rake and a `roots`
run over a stack's `f32` column. `safe_root.c` performs the same operation
with a C `for` loop and an `if`: non-negative values take their square roots,
and every other value becomes zero.

Run the bounded comparison in the pinned development shell:

```sh
nix develop --command dune build
nix develop --command bash demo/safe-root/run.sh
```

The Rake profile is AVX2: eight floats in a 256-bit register. The compiler
generates the complete loop and advances by eight elements per iteration.
One million elements require 125,000 full racks. A second correctness pass
uses 1,000,003 elements, including a three-lane final rack. Rake's native
object verifier checks the complete function against its selected assembly.
Generated C, objects and both disassemblies go under `.build/safe-root/`.

The independent C harness compares every result bit, checks empty counts,
all tail remainders, exact in-place output and allocations ending at guard
pages. Negative zero, quiet NaNs, infinities and ordinary signed inputs are
included. Inactive lanes must not cause arithmetic exceptions. A two-column
fixture also compares the native program with Rake's selected-profile
interpreter, including an unused byte column and a one-lane tail.

The timing input is one million pseudo-random finite floats, roughly half
negative, generated by xorshift32 from seed `0x31415926`. Four warmups precede
31 timed samples, with C and Rake alternating first position. Each sample
averages four complete passes and the report gives the median. The arrays
share the same initial data, and no link-time optimization is enabled.

Two C builds are reported. The ordinary optimized build uses GCC `-O3
-mavx2 -ffp-contract=off -fno-fast-math -fno-math-errno`. Its automatic
vectorizer is enabled. The explicitly scalar comparison adds
`-fno-tree-vectorize`. The report records all flags, compiler revision, GCC
version and processor. The scalar comparison illustrates lane parallelism;
it is not evidence that Rake beats optimized C.

On a Ryzen 7 5800X3D with GCC 14.3, both optimized C and Rake took roughly
0.15 ms per pass. The scalar build took roughly 4 ms. GCC had already
vectorized the optimized C loop. Rake's distinction in this example is
checked vector lowering, rather than a speed advantage over that C build.
Timings depend on processor, inputs, caches and other machine activity.
